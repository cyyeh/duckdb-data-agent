# i18n Design: English + Traditional Chinese

**Date:** 2026-02-20
**Scope:** Frontend UI strings only (not AI agent responses)
**Languages:** English (`en`), Traditional Chinese (`zh-TW`)

## Approach

Custom React Context + JSON translation files. Zero new dependencies. Mirrors the existing `ThemeContext` pattern.

## Architecture

### New Files

- `frontend/src/i18n/en.json` — English translation strings
- `frontend/src/i18n/zh-TW.json` — Traditional Chinese translation strings
- `frontend/src/LanguageContext.tsx` — Language state, provider, and `useTranslation` hook

### Modified Files

- `frontend/src/App.tsx` — Wrap with `LanguageProvider`, add language toggle in header
- All component files — Replace hardcoded strings with `t('key')` calls

### Language Detection Priority

1. `localStorage.getItem('language')` (user's saved preference)
2. `navigator.language` — if starts with `zh`, use `zh-TW`; otherwise `en`
3. Fallback: `en`

### LanguageContext API

```typescript
type Language = 'en' | 'zh-TW';

interface LanguageContextType {
  language: Language;
  setLanguage: (lang: Language) => void;
  t: (key: string, params?: Record<string, string | number>) => string;
}
```

The `t()` function:
- Looks up the key in the current language's translation file
- Supports simple interpolation: `t('rows', { count: 5 })` replaces `{count}` in the string
- Falls back to returning the key itself if not found

## UI Toggle

- **Position:** Header, immediately left of the sun/moon theme toggle
- **Style:** Same button styling as theme toggle
- **Label:** Shows `EN` when in English, `中` when in Traditional Chinese
- **Behavior:** Click toggles between the two languages
- **Accessibility:** `aria-label` of "Switch to 中文" / "Switch to English"

## Translation Keys

~40 flat key-value pairs covering: app title, mode labels, upload text, query editor placeholders, sidebar labels, agent panel text, chat input, message bubbles, results table, tool names, confirmation dialogs, error messages.

Both language files use identical keys.

## Data Flow

```
User clicks toggle → setLanguage('zh-TW') → localStorage updated
→ LanguageContext re-renders → all t() calls return new language strings
→ UI updates instantly (no page reload)
→ document.documentElement.lang updated for accessibility
```

## Edge Cases

- **Invalid localStorage value:** Falls back to OS detection, then `en`
- **OS language not zh or en:** Defaults to `en`
- **Missing translation key:** Returns the key itself (non-breaking fallback)
- **HTML `lang` attribute:** Updated on `<html>` element when language changes

## Out of Scope (YAGNI)

- RTL support (neither language needs it)
- Number/date formatting (app uses raw SQL output)
- Plural rules (using `{count} row(s)` pattern)
- Namespacing (only ~40 keys)
- Lazy loading of translations (files are tiny)
- Backend/agent translation (excluded per design decision)
